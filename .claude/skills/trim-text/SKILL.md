# 文章の削減（trim-text）

ページの文章から、削除しても情報が減らない文を探して減らし、根拠のない記述や不正確・不自然な表現を直す。必ず「候補の一覧 → 持ち主の確認 → 反映」の順で進め、確認なしに消したり書き換えたりしない。

## 1. 対象を読む
- 日本語のページ（例：gaussian/*.html）の本文、data-ja、`<span data-lang="ja">` を読む。en/ は生成物なので読まない。
- 範囲の指定がなければ、依頼されたページ群をすべて見る。

## 2. 削除候補の基準
次に当てはまる文・要素を候補にする。

- **ページの目的の言い直し**：「〜を1行ずつ」「初心者向けに短く説明します」のような、自分のページを説明するだけの文。
- **すぐ下と重複する要約**：直下の節を並べただけの一覧、目次と同じ内容の紹介文、直上の対処を繰り返すだけの注意。
- **同じページの別の場所との重複**：同じ注意・手順・数値が、本文・式の節・「注意」の枠などに2回以上あるもの。最もふさわしい1か所に残す。
- **一般的すぎる注意**：「オプションを足す前に構造を確認」「比較する計算は同じ条件で」のように、具体的な場面のページ（エラー対応・計算ガイドなど）に同じことが書いてあるもの。
- **宣伝的・雑談的な一言**：「無料でここまでできる」「〜に便利」「定番」「国産」「〜の前段に」「慣れるまでは〜」「ここで間違えると全部やり直し」。
- **古くなりやすい事情**：申請方法・料金・日付つきの記述、旧組織名、「担当者に確認します」。
- **この水準には細かすぎる話**：特定の機能の得意分野の列挙など、入門では使わない情報。
- **念押しだけの否定**：「〜の証明ではありません」「〜ではなく」のうち、前後で十分に分かるもの。打ち消す対象がページにない否定。
- **同じ断り書きの繰り返し**：複数ページにある同文は、必要なページだけに残す。
- **数や内容が合わなくなった文**：「よくある2つの形」なのに例が3つ、など。
- **ページの中身を並べただけの紹介文**：見出し直下の「考え方 → 手順 → 計算条件」「話題ごとに〜を1ページにまとめています」など、目次と同じことを言う文（検索用の meta description は別なので残す）。
- **細かすぎる注記・自明な確認**：「出力ではこの綴りで出力されます」、「参照する .chk が正しいものであることを確認します」のように、手順の中で当然行うことを改めて言うだけの文。
- **根拠のない独自の決まり**：出典のない閾値・回数・順番（「固有値が 1×10⁻⁴ 以下なら」「5サイクルだけ」「1回だけ」「第一候補・第二候補」）や、「条件を満たす〜だけに使います」のように中身の分からない条件。Gaussian の決まりのように読めるものは、一般的な書き方（用途と、あとで必ず行う確認）に直す案を出す。
- **断定しすぎ・打ち消し合う記述**：例外のあることを言い切る文（「存在率は G で求めます」→「通常は G」）、ページ内で言い方がずれているもの、「〜してから変換します（順序は結果に影響しません）」のように後半が前半を打ち消す文。
- **不正確な言い換え**：キーワードの働きを大まかに言い換えて意味が変わるもの（例：SCF=XQC は「二次収束法に切り替え」ではなく「通常の方法で収束しないとき二次収束法を追加」）。公式マニュアルの説明に合わせる。
- **ページ内の基準・表記の不一致**：「時間の目安：基準（1）」が同じページに2つある、記号のイタリック・下付きが場所によって違う、文末（「〜します」と「〜してください」）がそろっていない、など。
- **不自然な言い回し**：削除ではなく言い換えで直すもの（「〜した印」「印字」→「〜を示す出力」「出力」など）も、候補に含めてよい（短縮案として出す）。

## 3. 残すもの
- 手順、計算条件、数値、式、入力例、文献・リンク、構造に必要な見出し。
- その話題に固有で、具体的な誤りを防ぐ注意（例：校正係数を別の条件へ流用しない、虚振動を確認する、ルート行の下の空行の位置）。
- 持ち主が指定・承認した文（会話や過去の修正で決まったもの）。
- 科学的な内容は、候補として理由を示し、持ち主が選んだものだけを直す。直すときは公式マニュアル・原著に合わせ、照合できなかった場合はそのことを報告する。

## 4. 候補の一覧を出す
- ページの順に、場所（見出し・id）、今の文（そのまま）、理由（上の基準のどれか）、対応（削除／短縮案／修正案）を書く。
- 過去に持ち主が指摘・修正した内容（会話や PR の履歴）と同じ種類の問題が、ほかのページに残っていないかも確かめる。
- 推奨度を付ける：◎ 削除・短縮を推奨、△ どちらでもよい、× 残すことを推奨（理由つき）。
- 持ち主に、どれを反映するか選んでもらう。

## 5. 反映する
- 文字だけの要素は本文と data-ja・data-en を、リンクなどを含む文は `<span data-lang="ja">` と `<template data-lang="en">` 内の英語を、対応させて直す。
- 文字列の置き換えは、置き換える前の文字列が見込んだ回数だけあることを確かめてから行う。空になった `<p>`・`<li>`・注意の枠は要素ごと消す。
- 紹介文を変えたら、同じ文を使う meta description・og:description・入口ページのカードも合わせる。
- 節を消したら、その id へのリンク（ページ内の目次、ほかのページ、テスト）が残っていないかを確かめる。同じ内容を別のページ（例：キーワード一覧とエラー対応）にも書いている場合は、両方をそろえる。
- `python3 _dev/build_en.py` で英語版を作り直し、_dev/tests のテストを実行して、結果を報告する（.claude/CLAUDE.md に従う）。
