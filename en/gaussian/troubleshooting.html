Troubleshooting Gaussian errors

How to find the error

Look at the end of the output file (.log/.out). The cause is printed a few lines above Error termination. If there is no termination line at all, the job may still be running or may have been killed by a time, memory or disk limit.

Input format errors (the job stops before calculating)

If the output is short and ends with Error termination in l1.exe (route-line errors), l101.exe, l202.exe or l301.exe, the input file is almost certainly the problem. Check in order:

  1. Blank lines: one after the route line, one after the title, one after the coordinates.
  2. Spelling on the route line (Opt Freq, B3LYP, 6-31G(d)).
  3. Exactly one charge/multiplicity line.
  4. Coordinates in four columns (symbol x y z), with no full-width characters (including full-width spaces).
  5. A blank line after any extra input such as ModRedundant or a basis-set block.

A correct example is in Anatomy of an input file.

Missing blank line after the coordinates

End of file in ZSymb.

Cause: The coordinates (molecule specification) cannot be read: the blank line after the coordinates is missing, or Geom=Check was forgotten when the coordinates were meant to come from the .chk. It also appears when Opt=QST2 or QST3 does not have its two or three molecule specifications (title line, charge and multiplicity, coordinates).

What to do: Add a blank line after the coordinates, or add Geom=Check to the route line. For QST2 or QST3, check the number of molecule specifications.

Syntax error in an input line

QPErr --- A syntax error was detected in the input line.

Cause: Gaussian could not read an input line. The line is printed below the error, with ' under the place where reading stopped. Besides the route line, this also happens with input that is read later in the job (for example the atom list for NMR=ReadAtoms), so the job can stop after it has already run for hours.

What to do: Correct the printed line to the input format of that keyword in the Gaussian manual.

Charge/multiplicity does not match the electron count

The combination of multiplicity 1 and 9 electrons is impossible.

Cause: The electron count from the charge cannot have this multiplicity. An even number of electrons needs an odd multiplicity (1, 3, …); an odd number needs an even one (2, 4, …).

What to do: Correct the charge or multiplicity. Check for a radical given multiplicity 1, an ion whose charge was not changed, or a structure with too many or too few hydrogens.

Element not in the basis set

Atomic number out of range for 6-31G basis set.

Cause: The structure contains an element for which the basis set is not defined (for example, I or Pt with 6-31G(d)).

What to do: Choose a basis set that covers the element, or use Gen/GenECP to give a basis set (with an effective core potential for heavy elements) for each element.

Atoms too close

Small interatomic distances encountered:  6  1  7  2 ...
Problem with the distance matrix.

Cause: Two or more atoms are too close (sometimes on top of each other). The line above lists the numbers of the atoms in pairs. Pasting a structure twice in a viewer can cause this.

What to do: Fix the coordinates of the listed atoms, or delete the extra atoms.

Memory, disk and checkpoint errors

Memory cannot be allocated

galloc:  could not allocate memory.

Cause: The memory requested with %mem cannot be allocated.

What to do: Set %mem below the free memory of the machine. When running through a job scheduler, request more memory than %mem, because Gaussian uses more than %mem.

Out of disk space

Erroneous write. Write -1 instead of 3648000.

Cause: The disk for the scratch files is full, or the disk quota has been exceeded.

What to do: Delete unneeded files (such as scratch files left by jobs that stopped), or put the scratch on a disk with more space (GAUSS_SCRDIR), and rerun.

Checkpoint or scratch file cannot be read

Operation on file out of range.
...
Error termination in NtrErr:
NtrErr Called from FileIO.

Cause: Information requested from the .chk with Geom=AllCheck, Guess=Read, Opt=ReadFC and so on is not there: the %chk file name is wrong, or the earlier job stopped before writing it. It can also appear part-way through a job that reads nothing from a .chk (such as Opt Freq); then a scratch file of the job itself could not be read, and the output does not show why. Instead of Operation on file out of range., the line can be FileIO operation on non-existent file.

What to do: Check the %chk file name and location. If the earlier job stopped part-way, rerun from coordinates without that .chk. For a job that reads nothing from a .chk, check the free space of the scratch disk and that no scratch files were deleted during the job, and rerun.
