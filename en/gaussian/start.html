The workflow is the same everywhere: write the input file (.gjf/.com) locally, send it to the machine and run it, then bring the output (.log/.out) back to inspect.

1. Anatomy of an input file

A Gaussian input is a plain text file (.gjf or .com). It consists of five parts, top to bottom, with one blank line after the route line, after the title and after the coordinates.

%nprocshared=8                                    ← (1) Link 0: cores, memory, checkpoint name
%mem=16GB
%chk=catechin_opt_freq.chk
#p B3LYP/6-31G(d) Opt Freq                         ← (2) route line: method and job type
                                                   ← blank line
(+)-catechin  Opt+Freq                             ← (3) title: free text
                                                   ← blank line
0 1                                                ← (4) charge multiplicity
C   -1.692270  -0.992002   1.262321                ← (5) coordinates: symbol x y z (Å)
C   -0.275413  -1.265444   0.763977
 ...
                                                   ← blank line at the end
Part Contents
(1) Link 0 Lines starting with %: number of cores (%nprocshared), memory (%mem) and checkpoint name (%chk). Set cores and memory for the machine you run on.
(2) Route line Line starting with #. Method/basis set and job type (Opt, Freq, ...).
(3) Title A free-text note; it does not affect the calculation.
(4) Charge and multiplicity A neutral closed-shell molecule is “0 1”; a singly charged cation such as a protonated molecule is “1 1”; a singly charged anion such as a deprotonated molecule is “-1 1”; a neutral radical (doublet) is “0 2”.
(5) Coordinates One atom per line: element symbol and x, y, z in Å.

Reading the route line

  • #p — output verbosity. #n (or just #) is normal, #p adds per-step information, #t is terse. #p is easiest to check while learning.
  • B3LYP — the functional: how electron–electron interactions are approximated.
  • 6-31G(d) — the basis set: the functions used to describe the electron distribution.
  • Opt Freq — optimize the geometry, then compute vibrational frequencies at the same geometry.

Terms are collected in the glossary; how to choose methods is in the Calculation guide.

Making one for your own molecule

One example workflow.

  1. Draw the structure in ChemDraw (or the free ReShiki) and save as .mol

    Specify stereochemistry with wedge/hash bonds. Where to get the software is listed under Computational chemistry software.

  2. Open in Avogadro, make it 3D, check stereochemistry and optimize lightly

    Open the .mol in Avogadro 2 and add hydrogens if any are missing. Choose the MMFF94 force field, optimize the structure, check that the stereochemistry is correct, and save as .mol2.

  3. Run an MMFF conformer search in Spartan

    Load the .mol2 and run Calculations → Conformer Distribution. The conformers are the starting point of Conformers and stable structures. For a first run, use only the lowest-energy one.

  4. Turn it into a Gaussian input

    Export coordinates from Spartan, or create the input with Input → Gaussian in Avogadro 2; write the job type, functional, basis set and solvent on the route line, and save the .gjf.

Check stereochemistry and charge before exporting.

3. Run it

How you launch a job depends on the machine.

# Direct execution on Linux
g16 catechin_opt_freq.gjf

# With a job scheduler (e.g. Slurm), submit following the procedure of the machine you use
# (run_g16.sh is a job script prepared for that machine)
sbatch run_g16.sh

# On RCCS
g16sub catechin_opt_freq.gjf

The output is written to catechin_opt_freq.log (.out on some systems). On shared machines, set %nprocshared and %mem to that machine's rules (on RCCS, g16sub sets them from the resources requested at submission).

4. Reading the output: check three places

The output is long, but success is decided by three things. Use your text editor's search.

  1. Does it end with Normal termination?
     Normal termination of Gaussian 16 at ...

    With Opt Freq the frequency job follows the optimization, so this line appears twice. If you see Error termination instead, the cause is printed a few lines above it.

  2. Did the optimization converge?
             Item               Value     Threshold  Converged?
 Maximum Force            0.000012     0.000450     YES
 RMS     Force            0.000003     0.000300     YES
 Maximum Displacement     0.000891     0.001800     YES
 RMS     Displacement     0.000210     0.001200     YES
 Predicted change in Energy=-1.234567D-08
 Optimization completed.
    -- Stationary point found.

    "Stationary point found" means converged (normally all four items are YES). The table is printed at every optimization cycle. With Opt Freq it is printed once more at the end of the frequency job; check that it is all YES there as well.

  3. Are there no imaginary frequencies?
     Frequencies --     35.1234     58.9012     84.5678
 Red. masses --      3.4567      2.3456      4.5678

    If the values on the first Frequencies line are positive, the structure is a minimum. Even one negative value (e.g. -45.6) means it is not yet a minimum.

    The Freq output also contains thermochemistry. The free energy used for conformer comparison is this line:

     Sum of electronic and thermal Free Energies=          -1066.123456

5. When it stops: three common first errors

Text in the output Meaning What to do
 
Error termination via Lnk1e in .../l101.exe
 Input format error; the job stops before any calculation. Check the blank lines, the charge/multiplicity line and the coordinate columns. Spelling errors on the route line stop in l1.exe. 
Convergence failure -- run terminated.
 The SCF (electronic-structure iteration) did not converge.

Check charge/multiplicity and the structure, add SCF=XQC to the route line and rerun. Details

 
Number of steps exceeded,  NStep= ...
 The optimization did not converge within the cycle limit.

Continue from the last geometry in the output as a new input. Details
